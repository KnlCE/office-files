# Office Files 0.2.0

Local Astra tools for reading, creating and editing DOCX, XLSX and PPTX, and for reading and page-editing PDF, with the official Python SDK, python-docx, openpyxl, python-pptx and PDFium (pypdfium2). Microsoft Office is optional. LibreOffice enables Office→PDF/PNG export, legacy DOC/XLS/PPT conversion and formula recalculation; PDF reading, page editing and rendering need no LibreOffice.

Load this folder through **Plugins → Development**, or import the `.astraplugin` package. Set allowed directories (one absolute path per line; empty permits all accessible files) and the optional LibreOffice executable in standard settings. Tools are deferred through Tool Search and use Astra's current High confirmation level.

Use `office_help` with `language: "en"` for schemas and examples. Thirteen tools cover help/inspection, Word/Excel/PowerPoint create/edit, PDF page editing (`pdf_edit`: delete, keep/extract/split/reorder, rotate, move, insert another PDF's pages to merge), PDF export, PNG render, recalculation and conversion. `office_inspect` on a PDF returns one item per page (text, size in points, rotation, label) plus metadata, outline and `pages_without_text`; render scanned pages and read the PNGs with `read_image`. `pdf_edit` copies pages into a new document, so bookmarks, metadata and form fields are not carried over; text inside a PDF is not editable. Creates accept `output_path`/`spec`; edits require `input_path`, `output_path`, SHA-256 `revision` from inspection and typed `operations`. Inspection supports pagination/search; formulas and cached values are distinct. Slides use inches, Word millimetres, fonts points, indices zero-based.

Existing outputs require explicit `overwrite: true` and receive backups. Workers edit private copies; the parent rechecks revisions and commits validated results atomically. Unsupported features, lost package parts and changed untouched binary resources block saving. Text replacement refuses touched mixed text/drawing/field runs and special breaks. Macros, encryption, live Office control, SmartArt/animations and full Track Changes are outside scope. Excel worksheet copying excludes charts/images/tables; dependency-sensitive rename/delete and array formulas are refused. Immediate host cancellation, complete preservation of unknown XML extensions and identical Office rendering are not guaranteed.

See the Russian README for setup and limitations, `examples/` for files and portable specifications, `VERIFICATION.md` for validation. Install `requirements.txt` into `.venv`; run `pytest`, `astra-plugin check . --strict`, `astra-plugin test .`, `astra-plugin build . --reproducible`. Optional integration tests use `OFFICE_TEST_LIBREOFFICE`. Windows/Linux x64; Python≥3.10. Office Files is developed by KNICE and distributed under the MIT License.

Arguments in the shapes models actually send are repaired before validation: a nested object sent as a JSON string, `"true"`/`"false"` for a boolean, a numeric string for a number, and `path` for `input_path`. A repair fires only when the value has the wrong JSON type and parses into the right one.

PowerPoint geometry uses inches, not pixels: 16:9 is13.333×7.5. Example title: x0.8/y1.2/width11.7/height0.8. Objects outside the actual template canvas are rejected unless `allow_outside_slide: true` explicitly requests cropping. Create/edit/inspect return `layout_validation`, outside/empty warnings and `visual_verification: "not_performed"`. Use rendering to verify appearance; package health alone does not prove visible content.

**How to make one, not only which calls exist.** `office_help` with no `tool` returns `workflows` in the requested `language`: the order of work for a presentation, a document and a spreadsheet (plan → one `*_create` call → `office_render` → `read_image` → fix → render again) and slide design rules (`slide_design`). A `word_*`/`powerpoint_*` `create`/`edit` result carries `next_step`: the check still owed — render and look at every page or slide, or, without LibreOffice, say in the report that only the geometry was checked. The model reads every tool result, so the check is part of the work rather than something a system prompt has to remember (Astra's prompts never name a specific tool).
